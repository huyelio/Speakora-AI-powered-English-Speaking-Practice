# Learner UI redesign: direction A5 (warm retro)

Approved 2026-10-26. Replace the current learner UI with layout option A (skill-based navigation plus a "Bài nên học hôm nay" card on the home page) using visual direction A5. Frontend only: no migrations, no API contract changes, no worker changes.

The visual reference is [docs/design-preview/a5-hoai-co.html](../design-preview/a5-hoai-co.html). The other previews (`a1`–`a7`) are kept in the same folder as rejected alternatives for the record.

## Decisions

- **Light theme only.** Remove the theme toggle, the pre-paint `speakora-theme` script and every dark token block. Set `color-scheme: light`. A stored `speakora-theme` value is ignored, not migrated.
- **Navigation (layout A).** Top bar with pill tabs: Trang chủ, Từ vựng, Luyện nói, Luyện thi IELTS. Avatar menu holds Hồ sơ, Lịch sử luyện tập and Đăng xuất. Below 720px the tabs become a floating bottom tab bar with five items (Hồ sơ added).
- **Copy.** Vietnamese labels throughout. No "V2", no English uppercase eyebrows. English stays only for learning content (words, questions, transcripts).
- **Session URLs never change.** Only landing/setup pages move. Every in-progress session keeps the exact URL it has today (see Route map).
- **Recommendation card, first version.** Pure rule in `src/modules/dashboard/`: resume the latest unfinished Vocabulary Learning session (`getLatestLearningSessionId`); otherwise recommend the top topic from the existing `rankTopicRecommendations`. No new tables. Cross-mode progress is out of scope.
- **Out of scope here, next plan.** Cross-mode XP, streak, daily goal and history (vocabulary, pronunciation, role-play) need migrations. They get their own dated plan, written immediately after this one ships. That plan must also rename the home section "Phiên luyện nói gần đây" to "Hoạt động gần đây" once every mode writes history.

## Deviations log

Decisions taken during implementation that the plan did not cover are recorded here.

- **Phase 1, global retokenization.** `globals.css` held about 150 hard-coded purple/indigo/navy literals that tokens alone could not reach. A one-off script mapped each literal to the A5 semantic token for its hue and lightness role (`var()` for opaque, `color-mix()` for translucent). This happened in Phase 1 rather than screen by screen, so no old palette survives on screens restyled later. Pure black scrims and opaque white were left as they were.
- **Phase 1, typography.** The specimen showed stacked marks crowding at line-height 1.05, so h1–h3 default to 1.15 and the four heading rules below 1.15 were raised. Fraunces `WONK` is off. Letter-spacing tighter than −0.02em was relaxed to −0.02em across the legacy stylesheets.
- **Phase 1, brand logo.** The PNG logo (`public/images/brand`) is purple. Changing brand artwork is a brand decision, so the asset is kept unchanged. The app shell uses a text wordmark from Phase 2, while the auth pages keep the PNG.
- **Phase 2, IELTS resume.** The plan assumed signed-in IELTS state lived in `sessionStorage`. The code only stores guest sessions there; signed-in sessions are server-side and reopen from history. Behaviour is unchanged; the plan note and manual check were corrected.
- **Phase 2, links before hubs exist.** Until Phase 5 creates `/speaking`, the Luyện nói tab points at `/explore`. Từ vựng points at `/vocabulary` (the hub from Phase 4).
- **Phase 2, avatar on phones.** The avatar menu stays visible in the top bar on phones as well, so sign-out and history remain reachable; Hồ sơ is additionally the fifth bottom tab.
- **Phase 2, brand on in-app IELTS.** The practice topbar showed the raster logo for any IELTS session. It now shows it only for guests, because signed-in IELTS runs inside the app shell that already has the wordmark.
- **Phase 2, middleware coverage.** `/vocabulary`, `/pronunciation`, `/speaking` and `/ielts` were added to the auth middleware matcher and protected paths, so signed-out visitors get the sign-in redirect with `next=` before rendering. The `(learn)` layout check still applies.
- **Phase 3, no time estimates.** The preview showed "Khoảng 6 phút" on the card. No data backs a duration, so the card shows none rather than an invented number.
- **Phase 3, Vietnamese topic names.** Topic names are stored in English. Navigation-level UI (home card, recommendations, recent list, hubs) shows a Vietnamese label from `src/modules/topics/display-name.ts`, falling back to the stored name. Learning content stays English.
- **Phase 3, recommendations kept.** The home page keeps the ranked "Chủ đề gợi ý" list below the tickets, because it carries the personalised ranking that the single card only partly uses.
- **Phase 3, card components.** `DailyGoalCard` and `StreakCard` were replaced by one `ProgressTiles` component; their test assertions (bounded progressbar values) moved to the new component.
- **Interim links.** Each phase commit keeps every link working: tickets point at existing routes (`/pronunciation`, `/explore`, `/speaking/conversation`) until Phases 4 and 5 switch them to the hub URLs.
- **Phase 4, "Cần ôn lại" omitted.** No existing query lists weak words across sessions (weakness is derived per learning session), so the hub leaves the card out instead of faking it, as the plan allowed.
- **Phase 4, topic page CTA.** "Luyện từ vựng chủ đề này" now opens `/vocabulary?mode=learn&topic=<slug>` (it used to open flashcards), because Học từ mới is the primary vocabulary path. `LearningStart` gained an optional `preferredSlug` so the topic is preselected.
- **Phase 4, learn panel layout.** The old `/vocabulary-learning` setup lacked the `pron-setup-page` scope, so its level choices rendered unstyled. The hub adds that scope, making the learn and pronounce setups consistent.
- **Phase 4, session screens.** Flashcard, learning-step and pronunciation screens are restyled with CSS only (`src/app/a5.css`); markup and behaviour are unchanged. The learning session eyebrow shows the Vietnamese topic name.
- **Phase 4, auth redirect observation.** On a local production build, signed-out requests to protected routes (including the pre-existing `/dashboard`) return 200 with a streamed redirect to sign-in from the `(learn)` layout rather than a middleware 307. This predates the redesign and is unchanged by it.
- **Lint.** The repository has no `lint` script or ESLint config. "Lint" in phase verification means `npm run check` (strict `tsc`) plus the type and lint pass inside `next build`.

## Route map

Session routes stay as they are. Only the entry pages change.

| Today | After | How |
|---|---|---|
| `/dashboard` | `/dashboard` (new home) | Rewritten in place |
| `/vocabulary` (flashcard setup) | `/vocabulary` hub with Học từ mới / Ôn nhanh / Phát âm từ; `?mode=learn\|review\|pronounce` opens that mode's setup panel | Rewritten in place; `?topic=` still preselects a topic |
| `/vocabulary-learning` (setup) | `/vocabulary?mode=learn` | Permanent redirect, exact path only |
| `/pronunciation` (setup) | `/vocabulary?mode=pronounce` | Permanent redirect, exact path only; `?topic=` carried over |
| `/explore` | `/speaking?tab=topics` | Permanent redirect, exact path only; `?search=` and `?level=` carried over |
| `/speaking/conversation` without `session`/`scenario` | `/speaking?tab=roleplay` | Server redirect in the page, only when both params are absent |
| `/demo/speech` | Guests: unchanged. Signed-in: `/ielts` inside the app shell | Server redirect for signed-in users only |
| `/vocabulary/[sessionId]`, `/vocabulary-learning/[sessionId]`, `/pronunciation/[sessionId]`, `/practice/[sessionId]`, `/topics/[slug]`, `/speaking/conversation?session=…\|scenario=…`, `/history`, `/history/[sessionId]`, `/profile` | Unchanged URLs, restyled | — |

Redirect rules:

- Use `redirects()` in `next.config.mjs` with exact `source` paths (no `:path*`), so `[sessionId]` children never match.
- Next.js forwards the original query string, so `?topic=`, `?search=` and `?level=` survive.
- The existing `LEARNING_V2` redirect in `vocabulary/[sessionId]/page.tsx` stays.
- IELTS: only guest sessions are kept in `sessionStorage` (unchanged on `/demo/speech`). Signed-in IELTS sessions persist server-side and reopen from history at `/practice/<id>`; that URL is unchanged. (Corrected during Phase 2, see Deviations log.)

## Phases

Each phase ends with focused tests, `npm run check`, and the manual checklist for that phase. Phases 1 and 6 also run `npm test` and `npm run build`.

### Phase 1 — Tokens, fonts, theme removal

- [x] Create `src/app/tokens.css` with the A5 tokens from the preview (colors, radii, font variables). Components consume semantic tokens only.
- [x] Merge `globals.css` and `friendly-playful.css` into token-based styles. Delete the navy dark palette and every `[data-theme="dark"]` block. Leave `auth-welcome.css` and the CSS modules in place, retokenized.
- [x] Load Fraunces (opsz, SOFT, WONK axes) and Work Sans through `next/font/google` with `subsets: ["latin", "vietnamese"]`, exposed as CSS variables.
- [x] Remove `ThemeToggle` and its uses (`header-actions.tsx`, `auth-shell.tsx`, `onboarding-form.tsx`, `practice-session.tsx`) and the inline theme script in `src/app/layout.tsx`.
- [x] **Vietnamese diacritics check.** Build a temporary specimen at `docs/design-preview/fraunces-vietnamese.html`. Render these at 24, 36, 48, 60 and 96px, regular and italic, with the line-heights used for headings:
  - Luyện, Hồ sơ, Bài nên học hôm nay
  - Chào Lan, hôm nay mình đi đâu?
  - Ẩm thực & nấu ăn, Kế hoạch tương lai, Sức khỏe & thể chất
  - Thói quen hằng ngày, Nhớ từ, Ngữ cảnh, Tổng kết, Luyện thi IELTS
  - Ở, Ỗ, Ể, Ữ, Ậ, Ặ (worst-case stacked marks)

  Pass criteria:
  - The tone mark sits above the circumflex or breve and does not collide with the previous line.
  - Nothing is clipped by `overflow: hidden` containers.
  - Baselines line up when Fraunces and Work Sans share a line.

  If it fails, apply in this order: raise heading `line-height` to at least 1.15; turn off `WONK`; limit Fraunces to sizes of 28px and up and use Work Sans below that. Record the outcome in the design system spec.
- [x] Update [speakora-design-system.md](../specs/speakora-design-system.md): direction A5, tokens, light only, typography rules from the specimen.

## Risks

- **Large CSS merge.** About 3,500 lines across `globals.css` and `friendly-playful.css`. Retokenize screen by screen per phase instead of rewriting everything in Phase 1. Phase 1 only removes dark mode and introduces tokens and fonts.
- **Contrast.** White text on mustard fails contrast. Use brown on mustard, and cream only on orange, teal, olive and brown. Check every new pairing.
- **Redirect order.** Next.js applies `next.config` redirects before middleware. Confirm the Supabase auth middleware still sends signed-out users to sign-in with `next=` pointing at the new URL.
- **Guest IELTS.** Must keep guest-session authorization untouched. Do not move `/demo/speech` under the authenticated layout.

- Per phase: focused Vitest files for touched modules, then `npm run check`.
- Phases 1 and 6: `npm test` and `npm run build`.
- The manual checklists above require a running dev server with Supabase, worker, OpenAI and Azure credentials. Do not report a live recording, STT or assessment flow as verified unless it was actually exercised.
