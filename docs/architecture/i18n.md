# Language support

The UI is available in Vietnamese and English. Vietnamese is the default.

## How it works

- Vietnamese copy stays in the source as the key. `src/i18n/en.ts` maps each key to its English text.
- Server components call `const t = await getT()`. Client components call `const t = useT()`. Without a provider, `useT` is Vietnamese, so components render in tests without setup.
- `t("…")` only accepts keys in `en.ts`, so an untranslated string fails `npm run check`.
- Placeholders are `{0}`, `{1}`. A value such as `"{0} word|{0} words"` picks a plural form from the first placeholder.
- Copy held outside a component is wrapped in `msg("…")` and rendered with `t.dynamic(value)`. Render helpers take `t` as a parameter that defaults to `defaultT`. Browser-only fetch helpers use `browserT()`, which reads `<html lang>`.

## Storing the choice

- The `speakora-locale` cookie decides the language of a request (`getLocale`).
- `profiles.locale` keeps the choice on the account. `setLocale` writes both, and sign-in copies the profile value into the cookie (`src/modules/profile/locale.ts`).
- Learners change it in Profile → Settings. The auth pages have a VI | EN switch that only sets the cookie.

## AI feedback

Assessments are written in the learner's language: `assess(…, locale)` for practice and role-play. The worker reads `profiles.locale`, and guests get Vietnamese. Results saved earlier keep their language.

## Out of scope

- Error text returned by API routes and server modules stays Vietnamese unless the same string is in `en.ts` and rendered through `t.dynamic`.
- Logs and internal messages are not translated.
- Vocabulary meanings stay Vietnamese because they are learning content.
